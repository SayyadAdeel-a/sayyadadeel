# Relab — clone research index

Source: <https://relab-template.webflow.io/>
Site key: `relab-0c02b053` · 25 routes

This folder is the auditable record of how the clone was built. Every file in it
was produced by a script in `scripts/`, so the extraction can be re-run and
re-checked at any time.

## Scope

All 25 published routes are cloned: the homepage, nine static pages, `/changelog`,
`/404`, and fourteen CMS detail pages (6 blog posts, 5 case studies, 3 service
pages). The route list and each route's `<title>`, description and Open Graph
metadata are captured in `routes.json`.

The reference publishes **no** `/channel-logo` route — it answers 404, and no
page contains "channel logo" content — so that page does not exist in the clone
either.

## Layout

| Path | Contents |
| --- | --- |
| `routes.json` | every route: path, page key, title, description, OG metadata |
| `routes-manifest.json` | what `capture-pages.mjs` downloaded, per batch |

| `PAGE_TOPOLOGY.md` | every route's sections, component mapping and payload size |
| `PIPELINE.md` | how a live route becomes components, assets and a route file |
| `IX3-ENGINE.md` | Webflow's interaction engine, reverse-engineered and verified |
| `QA_REPORT.md` | measured parity results for all 25 routes |
| `qa/report.json` | machine-readable QA output |
| `qa/*-{1440,768,390}.png` | reference and clone screenshots per route |

Per-route research folders (`about-979bddc4/`, `case-studies-cecbd40a/`, …) hold
that page's captured source:

| File | What it is |
| --- | --- |
| `live-page.html` | the complete served HTML |
| `webflow-ix2.json` | the decoded IX3 interaction + timeline payload |
| `webflow-js/` | every runtime chunk the page loads |
| `scripts-inline/` | the page's own inline scripts |
| `live-webflow.css` | the site stylesheet, for provenance |
| `critical.css` | the page's inlined critical stylesheet |
| `asset-map.json` | CDN URL → local path for every asset it references |
| `raw-assets.json`, `image-variants.json` | raw asset inventories |

The homepage's folder (`root-8a5edab2/`) additionally has the original design
documentation — `DESIGN_TOKENS.md`, `BEHAVIORS.md`, `IX2-READABLE.md`,
`components/*.spec.md` — written when the clone began.

## How the clone is put together

```
app/
  layout.tsx                     fonts + webflow.css + globals.css + Lenis
  page.tsx                       / — the frozen homepage
  about/page.tsx                 ┐
  services/[…]/page.tsx           │ generated by scripts/convert-page.mjs,
  case-studies/[…]/page.tsx       │ one file per route, each importing
  blogs/[…]/page.tsx              │ its own critical.css + ix.json
  pricing|contact|licenses/…      ┘
  not-found.tsx                  renders the /404 markup
src/components/sites/adeel-site/
  root-8a5edab2/                  homepage sections (hand-authored, frozen)
  <page-key>/                     per-page sections (generated) + ix.json
  shared/
    SiteHeader|SiteCta|SiteFooter shared shell, parameterised by currentPath
    InteractionsRuntime.tsx       the homepage's own runtime (frozen)
    PageInteractions.tsx          runtime entry point for generated pages
    ix/runtime.ts                 Webflow IX3 interpreter
    ix/widgets.ts                 w-tabs / w-slider / w-form / background video
    ix/ease.ts, ix/types.ts       ease table and payload types
public/sites/adeel-site/
  root-8a5edab2/                  the homepage's own asset directory
  _pool/                          342 shared assets for all 24 other pages
```

## Reproduction

```bash
# Full pipeline for the 24 generated pages
npm run pipeline:capture     # HTML + runtime chunks + IX payload
npm run pipeline:registry    # routes.json
npm run pipeline:assets      # shared asset pool
npm run pipeline:styles      # per-page critical stylesheets
npm run pipeline:convert     # components + app/<route>/page.tsx
npm run build

# QA (needs `next start --port 3100` running)
npm run verify               # every route × 3 viewports
npm run verify:navigation    # every internal link resolves
npm run topology             # regenerate PAGE_TOPOLOGY.md
```

## Reading the results

`QA_REPORT.md` is the generated summary. The short version:

* **72 of 72** route-viewport combinations (25 routes × 1440 / 768 / 390) match
  the reference on document height, DOM outline, every element's bounding box
  and every scripted interaction;
* every route's rendered text matches exactly (25/25);
* every image matches — same asset, same intrinsic size, same `srcset` candidate
  count, same `sizes`, same `object-fit` (50 route-viewport combinations);
* all 25 internal link targets resolve, with the same status as the reference
  except `/404`, which Next.js answers with HTTP 404;
* full-page pixel diffs: the median route differs by **0.002%** of pixels, and 35
  of the 50 captures by less than 0.01%. Screenshot dimensions match exactly
  everywhere.

On the routes where the pixel diff is larger, the difference is *below the
reference's own reload-to-reload difference*: sections driven by infinite ambient
loops render at a different point of the loop on every load, so the reference
does not reproduce itself either. `QA_REPORT.md` shows both numbers side by side.

The homepage — frozen, built before this pipeline existed — still passes its own
original harnesses unchanged: 1691/1691 DOM nodes, 1836/1836 boxes with 0
mismatches, 0 of 16 behaviour checks differing.
